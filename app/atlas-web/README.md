# Mediterranean Multiproxy Atlas — web v3

Interactive scientific pilot: 5,846 source entries for cores/sites, 9,726 PANGAEA dataset references and 289 declared campaign labels. Quantitative collection: 29 marine/lake/speleothem records, 89 series, 81,339 archived values from PANGAEA and NOAA WDS Paleo. React/Vinext Worker + Cloudflare D1 (SQLite-compatible), Drizzle migrations, Leaflet. No Supabase account or client secret required.

- Scientific source, provenance, Python importers and manuscript: https://github.com/SantiCa/mediterranean-multiproxy-atlas (private).
- `data/inventory.json` is generated by `scripts/discovery/build_inventory.py`; it preserves source identity and coverage. Inventory CSV/search are paginated in D1; similar names/coordinates are not automatically merged.
- `data/seed.json` is generated by `scripts/build_quantitative_v3.py` in that repository. Never edit values here.
- `lib/science.mjs` defines fixed-reference z scores and bounded exploratory IDW; `node --test tests/science.test.mjs tests/timeline.test.mjs tests/proxies.test.mjs` checks its contracts.
- `npm ci`, `npm run dev`, `npx tsc --noEmit` for local development (Node >=22.13).
- Apply `drizzle/*.sql` to local D1 before first use. The `/api/bootstrap` endpoint then imports the versioned seed idempotently in small batches. Production migrations are deployment-owned.
- See `STARTER.md` for runtime/hosting instructions and the parent repository `docs/QUANTITATIVE_V3.md` for scientific limits and reproduction.

The site is owner-private. Publication does not change the scientific repository visibility. Basemaps are remote third-party services with visible attribution; they are not numerical bathymetry datasets. SVG exports use editable vector coast/data, not copied basemap tiles. Source DOI submissions are bibliographically verified review candidates; values are curated separately.

Moving windows preserve their width and a fixed z reference. Time extent uses all numerical records and explicitly labelled published metadata coverage. Series comparison supports selected/all compatible cores, raw/z values, window zoom, opacity, enlarged view and provenance-bearing SVG/CSV exports.

Proxy discovery uses metadata facets and lazy observation queries for one method/unit comparison group. Dense series use labelled visual-only thinning; full CSV/SVG points are preserved.
